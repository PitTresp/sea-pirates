# SEA Pirates – Learning Roadmap

Die Roadmap beschreibt die geplante Lernrichtung von SEA Pirates.

Sie ist keine starre Reihenfolge. Phasen dürfen aufgrund neuer Erkenntnisse,
AP2-Anforderungen oder praktischer Projektbedürfnisse angepasst werden.

## Phase 0 – The First Boot

Grundlagen des Projekts und der Entwicklungsumgebung.

- Visual Studio
- .NET
- Git/GitHub
- Repository-Struktur
- Lern- und Dokumentationsprozess

## Phase 1 – Everything is an Object

Grundlagen objektorientierter Programmierung.

- Klasse und Objekt
- Attribute/Felder
- Properties
- Methoden
- Konstruktoren
- Sichtbarkeit
- Kapselung
- Referenzen
- erste Codeanalyse

## Phase 2 – Thinking in Objects

Objektbeziehungen und Modellierung.

- Assoziation
- Aggregation
- Komposition
- Vererbung
- ist-ein / hat-ein
- Polymorphismus
- Composition over Inheritance
- UML-Grundlagen

## Phase 3 – Contracts

Abstraktion und Zusammenarbeit von Komponenten.

- Interfaces
- abstrakte Klassen
- Abhängigkeiten
- Dependency Injection
- SOLID-Grundlagen

## Phase 4 – Clean Engineering

Codequalität und Veränderbarkeit.

- Clean Code
- Naming
- Verantwortlichkeiten
- Code Smells
- Refactoring
- technische Schulden

## Phase 5 – Working with Data

Daten verarbeiten und persistieren.

- Collections
- Generics
- LINQ
- Dateien
- JSON
- relationale Datenbanken
- SQL
- Normalisierung
- Transaktionen

## Phase 6 – Architecture

Größere Anwendungen strukturieren.

- Separation of Concerns
- Schichten
- Services
- DTOs
- Persistenzabstraktion
- APIs
- HTTP und REST
- ausgewählte Design Patterns

## Phase 7 – Quality

Software systematisch absichern.

- Debugging
- Exceptions
- Logging
- Unit Tests
- Integrationstests
- Testentwurf
- AP2-relevante Testverfahren

## Phase 8 – Professional Engineering

Entwicklung im professionellen Kontext.

- Git-Workflows
- Branching
- Pull Requests
- Code Reviews
- CI/CD
- Releases
- technische Dokumentation
- Architekturentscheidungen

## Querschnitt: AP2

AP2-Vorbereitung ist keine einzelne Phase.

Sie begleitet das gesamte Projekt durch:

- prüfungsnahe Fragen
- Fachbegriffe
- Codeanalyse
- Pseudocode
- SQL
- UML
- Algorithmen
- Projektmanagement
- Wirtschafts- und Sozialkunde
- eine alte Prüfung pro Woche

## Zielzustand

Ein Thema gilt nicht allein deshalb als gelernt, weil seine Definition
bekannt ist.

Angestrebt wird die Entwicklung von:

1. gesehen
2. verstanden
3. selbst erklärt
4. praktisch angewendet
5. in unbekanntem Kontext erkannt und übertragen
